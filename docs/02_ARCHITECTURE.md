### Key Architectural Characteristics

- **Modular Monolith** — Single-parish deployment with zero distributed microservice complexity.
- **Login Gate & Security Envelopes** — **2 cổng đăng nhập UI, chung 1 backend auth (ADR-044/058)**: `/login` (chọn cổng) → `/login/phuhuynh` (SĐT + mật khẩu; quên mật khẩu phải liên hệ BGL qua kênh đã xác minh) hoặc `/login/nhan-su` (tên đăng nhập + mật khẩu, liên hệ BGL khi quên). **1 tài khoản = 1 vai trò** (`users.role` enum): đăng nhập sai cổng → role gate logout + chỉ đường sang cổng đúng (GLV kiêm PH dùng 2 tài khoản riêng). Backend dùng `POST /api/auth/login`; credential chỉ lưu bcrypt hash, mật khẩu tạm trả đúng một lần, không có reveal/KBA self-reset.
- **RBAC & Class Scope Guards** — `roleMiddleware` and `checkUserClassAccess` enforced across all REST endpoints. Client-side: TanStack Router `requireRole` guards per route; admin-only admin pages consolidated into the **"Quản Lý Hệ Thống" hub** (`/management` — tabs: Năm Học, Lớp Học, Tài Khoản); `/classes` + `/academic-years` + `/catechists` client guards là `admin`-only (server API roles: `/users/catechists` vẫn `admin + chunhiem`, xem `router.tsx:170`).
- **Automatic Viewport Adaptation (`useEffectiveMode`)** — Dynamically switches between Desktop (≥768px) and Mobile (<768px) components while respecting explicit user override mode in `filterStore`.
- **Presentation System v4.2 (`App-wide Calm, Confident Parish Product`, ADR-063/065)** — `src/index.css` là code truth cho surface/elevation/motion tokens; `PageHeader`, product-view/panel/toolbar/tab/entity/state/auth primitives và desktop/mobile shell classes tạo một visual grammar dùng chung. `PageTransition` + TanStack Router View Transition tạo fade-through ngắn cho pathname change trong vùng content, giữ shell đứng yên; search/filter-only navigation không animate, trình duyệt cũ có CSS fallback và `prefers-reduced-motion` tắt toàn bộ route motion. Chỉ brand shell được biểu đạt mạnh; content giữ data-first hierarchy. Mobile và desktop dùng component thích nghi riêng khi task density khác nhau, đồng thời giữ đúng một `#main-content` và semantic controls. `appWideUiMigration.test.ts` khóa inventory 13 desktop + 12 mobile + public/auth; `/management` dùng embedded child views để không lặp page hierarchy.
- **Capacitor Native Shell (2026-08-13)** — Dual-platform: Web (PWA, `vite-plugin-pwa` + `sw.ts`) **và** App native (Android/iOS) qua Capacitor 8 (`@capacitor/core` + `@capacitor/android` + `@capacitor/ios`, config `capacitor.config.json`, appId `com.tnttvn.app`, webDir `dist`). `useEffectiveMode` ép `mobile` mode khi `Capacitor.isNativePlatform()`. API base cho native build lấy từ `VITE_API_BASE` (production: `https://tnttvn-production.up.railway.app/api` — `.env.production`; dev web giữ proxy `/api` → `localhost:3001`). Web Push (`pushManager.ts`) tự disable trên native (không service worker — `isSupported()` false, không crash); push native dùng plugin `@capacitor/push-notifications` (backlog). Build: `npm run capacitor:sync` → `npx cap open android` (Gradle `assembleDebug` ra `app-debug.apk`); project native trong `android/` + `ios/` (đã commit cùng repo). Lưu ý build Windows: `android/local.properties` dùng **forward slashes** (`sdk.dir=C:/...`) vì Java Properties parse `\b`/`\u` làm hỏng path, và `JAVA_HOME` nên trỏ JDK 21 (Android Studio JBR). **CI/CD native qua Codemagic** (`codemagic.yaml`, ADR-029): workflow `ios` build web → `cap sync ios` → `xcode-project build-ipa` (auto signing) → TestFlight; workflow `android` → `gradlew assembleDebug` → artifact APK. Không cần máy Mac — runner macOS cloud của Codemagic (free tier ~500 build phút/tháng; TestFlight yêu cầu Apple Developer $99/năm). **Sideload iOS không cần Apple Developer (2026-08-19)**: workflow GitHub Actions `.github/workflows/ios-ipa.yml` (trigger thủ công) build **IPA unsigned** trên runner `macos-15` (`xcodebuild archive` với `CODE_SIGNING_ALLOWED=NO`) → artifact `tnttvn-ipa` → cài qua Sideloadly/AltStore (tự ký lại bằng Apple ID free, re-sign mỗi 7 ngày). Codemagic giữ vai trò pipeline chính thức (TestFlight/App Store). **CORS native (2026-08-19, A-NEW-58)**: production allowlist thêm origin native shell — `capacitor://localhost` (iOS), `https://localhost` (Android Capacitor 8), `http://localhost` (Android < 8) — fix normalize origin cho scheme tùy chỉnh (opaque origin), xem `server/src/utils/originPolicy.ts`.
- **Offline Sync Engine (`useSyncEngine`)** — 4-phase push pipeline + delta pull:
  1. **Phase 1 — Compact & Flush**: merge duplicate ops in the queue, then flush batched UPDATEs. Safe compaction rule: `CREATE` + `DELETE` pairs only canceled if `CREATE` is unsent local-only (`pending` status, `retryCount` 0). If `CREATE` has retried, keep BOTH `CREATE` and `DELETE` so Phase 1.5 retries `CREATE` with `idempotencyKey`, remaps Temp ID to Server Real ID, and Phase 3 executes `DELETE` with real ID (zero lost mutation).
  2. **Phase 1.5 — Parent CREATEs first**: parent entities (student/class/notice/exam) are created with `idempotencyKey` and client temp IDs remapped to server IDs BEFORE dependents sync.
  3. **Phase 2 — Group batchable ops**: grade/attendance UPDATEs grouped into batch requests.
  4. **Phase 3 — Individual ops**: student/class/notice/exam CREATE, DELETE and non-UPDATE ops processed one-by-one.
  Then **Pull Delta** (`fetchAllData`) refreshes client state.
  - Conflict handling: LWW field-level merge on version conflict for Grade/Attendance (client edit kept), Server-Wins for Student/Class/Notice/Exam CRUD (with explicit Toast separation). Strict Optimistic Concurrency Control (OCC) version enforcement, exponential backoff. Retry thresholds: server/client errors retry up to 3 (`MAX_RETRIES`), network errors bypass the cap up to 5 attempts. Dexie operations wrapped in atomic `db.transaction`. User isolation enforced fail-closed (`isOwnOp`) with 1-time `migrateLegacyQueueUserIds`.
- **CQRS Read Model Projections** — Pure SQL read repositories (`ReportCardProjectionRepository`, `ClassSummaryProjectionRepository`) separate from write models (4 Drizzle write repositories).
- **Fail-Closed Database Readiness (ADR-051, 2026-08-21)** — `db/index.ts` vẫn thực thi bootstrap + versioned migrations, nhưng `server/src/index.ts` bắt buộc gọi `assertDatabaseReady(client)` **trước seed, bind HTTP port và background workers**. Gate kiểm toàn bộ migration manifest có chủ đích, tenant/data-integrity unique indexes, integrity triggers, cột migration quan trọng, composite PK `(parish_id,id)` của bảng critical và `PRAGMA foreign_key_check`. Bất kỳ migration bị log-and-continue nhưng không ghi marker, hoặc executable schema thiếu guard, đều làm startup fail-closed; ứng dụng không được phục vụ traffic trên partial schema.
- **Atomic Finance Command Boundary (ADR-051, 2026-08-21)** — mọi Finance write (`createFund`, `createTransaction`, `deleteTransaction`, `updateStudentFee`) có implementation duy nhất trong `FinanceApplicationService` và chạy qua `runDbTransaction`. `updateStudentFee` tái sử dụng `createTransactionInTx` để payment ledger + audit + fee record dùng cùng transaction, không nested transaction; legacy `financeService.ts` chỉ giữ query/read logic và re-export command để import cũ không bypass ACID boundary.
- **Scan Engine v4 trust + performance boundary (ADR-049/050/060/062)** — Camera/QR/OMR xử lý on-device; T3 ràng buộc identity + template + số câu + mã đề A–H vào checksum, còn T2/TE/legacy map về A. Live QR xen 3 lượt `live_fast` (3 ROI thường) với 1 lượt `live_recovery` (một crop focus phóng 2×), đều không inversion; explicit capture/file/batch mới dùng `exhaustive` 9 normal + 4 `invertFirst`; Code128 giữ fallback ở mọi mode. Detector chuẩn bị grayscale+SAT một lượt, tái sử dụng SAT giữa locators, short-circuit marker thiếu và dùng scratch arena ≤2,5 triệu pixel; ảnh still lớn hơn dùng buffer cục bộ, arena được zeroize/release khi camera hoặc batch kết thúc. Auto camera dùng 960px cho candidate đầu, 1280px cho QR/recheck/frame xác nhận cuối; fixed-student still tối đa 2200px và upload tối đa 1400px. RAF gọi callback cấu hình mới nhất và backpressure neo sau thời điểm xử lý xong; async generation token chặn capture/upload/batch tiếp tục sau unmount; 2-frame consensus, mọi marker/paper/geometry/confidence gate và server recompute giữ nguyên. Quality bad chặn sớm; live batch giữ stream, file batch commit UI mỗi 8 ảnh nhưng yield sau từng ảnh và accepted-only proposal. `scan_metadata` cấm ảnh và gắn `omr-v4-*`; diagnostics local v2 chỉ histogram/counter, snapshot rà soát vẫn opt-in AES-GCM local TTL 24h, không upload. KPI MC tách exact engine/device/runtime/resolution/template/questionCount/cold-warm và required matrix rỗng/missing fail-closed; corpus camera ADR-060 chưa đủ nên unattended/default auto-batch vẫn CONDITIONAL, score-grid written luôn manual-confirm; SBD/OCR tiếp tục đóng.
- **Supervised Continuous OMR Queue (ADR-067, 2026-08-28)** — Khi người chấm bật `Quét liên tiếp`, explicit Save ghi trước một mutation mã hóa riêng theo `sessionId + studentId`, optimistic result và durable item ledger; camera re-arm ngay mà không chờ network/full refresh. `complete` là session barrier sau các save/remove. Attempt fingerprint chặn duplicate, same-student/different-attempt phải xác nhận conflict, re-arm cần identity mới hoặc old-sheet absence 3 observation/≥900ms. Server migration `20260828-135` lưu receipt `exam_result_mutations` theo `(parish,user,clientMutationId)` trong cùng transaction với result: retry cùng hash trả acknowledgement `duplicate` không ghi lại/audit lại; key trùng payload khác trả 409. Response itemized reconcile điểm server và UI `pending/synced/conflict/error`. `VITE_CONTINUOUS_SCAN_V2` là rollback flag; stable mode và toàn bộ OMR/identity/quality/human-confirm/privacy gate giữ nguyên. Field accuracy/unattended vẫn bị khóa bởi ADR-060.
- **Mixed exam scoring boundary (ADR-053, 2026-08-24)** — Phiên `exam_type='mixed'` (đề TN + TL): `question_count` = số câu TN, câu TN phải chiếm index 1..N liên tục; server tổng hợp `score = Σ points câu TN đúng + essay_score` (không dùng tỉ lệ thang như MC thuần), merge 2 pha quét/nhập-tay giữ nguyên thành phần đã lưu. Parser đề mixed chạy client-side như pipeline import hiện hữu; OCR chấm bài viết tay vẫn BLOCKED — phần TL nhập tay qua QuickScoreEntry/GuidedGrade.
- **Exam Export Subsystem (2026-08-19)** — `src/utils/examExporter.ts` + `ExamExportModal.tsx`: Hỗ trợ xuất đề thi và bảng đáp án đa định dạng 100% offline không cần backend. Hỗ trợ 6 định dạng: (1) **Microsoft Word (.doc)**: định dạng in ấn A4, tiêu đề Giáo Phận/Giáo Xứ, khung thông tin học sinh, ô trả lời trắc nghiệm nhanh, 1 hoặc 2 cột, bảng đáp án và giải thích chi tiết cho GLV; (2) **Excel (.xlsx)**: tạo file đa sheet (`Danh_Sach_Cau_Hoi` tương thích import, `Bang_Dap_An_Ma_De` ma trận đáp án mã đề A–H, `Thong_Tin_De_Thi`); (3) **Plain Text (.txt)**; (4) **Markdown (.md)**; (5) **JSON (.json)**; (6) **PDF / In ấn**. Tích hợp trực tiếp vào `ExamSessionView`, `ExamPaperModal`, và `ExamImportModal`. Mọi đầu ra HTML đều được escape (`escapeHtml`) chống XSS.
- **Outbox & Notification Infra** — `outboxService.ts` (outbox-message pattern) + `notificationQueue.ts` (retryable delivery queue, ADR-014) + `telegram.ts`/`smartNotifications.ts`/`webPushService.ts` for notifications. Web push end-to-end: client `pushManager.ts` + `public/sw.js` (SW nhận push khi app đóng), server `webPushService.ts` là SSOT gửi (`/notifications/send` + queue đều đi qua), queue không còn đánh dấu `sent` giả — VAPID thiếu → `failed`. Web push **CÓ CHỦ ĐÍCH**: `sendWebPushToUsers` lọc theo `user_id`; `notifyParishNotice` gửi phụ huynh khớp phone (SSOT `phoneMatchVariants` + `CanAccessStudentSpecification`) theo `targetBranch`, persist `notifications.target_user_ids` để recover không broadcast nhầm (ADR-022). Offline sync engine hardening follows ADR-016 (queue user-scoping, temp-ID remap before dependent sync, per-request zod batch isolation, `lastSyncAt` timing, transient-failed promotion, per-user queue compaction).
- **Cổng Phụ Huynh** — `GET /api/parents/my-children` (role `phuhuynh`, `parentService.ts`) + `src/pages/ParentPage.tsx` (route `/parent`, tab "Con Của Tôi" thay Thiếu Nhi/Điểm Danh/Bảng Điểm/Báo Cáo cho phụ huynh; phiếu điểm qua `ReportViewModelFactory`/`GET /api/reports/report-card/:studentId`; **xin phép nghỉ 2026-08-22**: nút "Xin Phép Nghỉ" + lịch sử đơn/hủy đơn PENDING dùng chung `LeaveRequestModal`/`leaveRequestStore` với dashboard). **Dashboard riêng cho PH**: `src/pages/DashboardPage.tsx` render `src/components/common/ParentDashboard.tsx` (responsive desktop + mobile) khi role = `phuhuynh` — greeting, chọn con (chip), thẻ điểm HK1/HK2/Xếp Loại/Chuyên Cần, kết quả năm (promotion), lịch sử đơn xin nghỉ, thông báo mới nhất (`useNoticeStore`), CTA sang `/parent` để in phiếu điểm. Data fetching SSOT: `src/hooks/useParentPortal.ts` (children + report card, dùng chung cho `ParentDashboard` và `ParentPage`). **Widget trình bày dùng chung (2026-08-22)**: `src/components/common/ParentWidgets.tsx` (ChildAvatar gradient chữ cái đầu, AttendanceBar tiến độ Lễ/Giáo lý, StatCard, DonutRing chuyên cần SVG thuần, PromotionBanner tông màu theo kết quả) + helper màu học lực/avatar ở `src/utils/parentDisplay.ts` — dùng chung 2 màn hình PH, bám DS token nên tự thích ứng dark mode; hero dashboard dùng gradient parish-primary. Liên kết PH ↔ con bằng số điện thoại chuẩn hóa (`utils/phone.ts`) — quyết định ADR-022 (Option A decision matrix: 9/9/9 vs Option B 6/6/6).
- **Cấp Tài Khoản Phụ Huynh Hàng Loạt (Parent Provisioning, ADR-026)** — `GET /api/users/parent-provision-preview` + `POST /api/users/provision-parents` (admin-only + re-auth `adminPassword` chuẩn A06 + `adminReauthRateLimiter`): scan `students.parentPhone` cùng giáo xứ → normalize/dedupe SĐT (anh chị em cùng SĐT → 1 account `childrenCount`), skip placeholder `'Chưa cập nhật'`/invalid/đã có user/trùng username trong cùng giáo xứ (`(parish_id, username)` UNIQUE — ADR-046); tạo `role='phuhuynh'`, username = SĐT chuẩn hóa, temp pass `Parish@\d{6}` + `FORCE_PASSWORD_CHANGE` (policy §10.1/§10.2), bcrypt 12, `passwordEncrypted` theo ADR-021, **không** gán `catechistAssignments` (fix: `createUser` chỉ gán lớp cho `chunhiem`/`phuta`). Cửa sổ **7 ngày** (`UNDO_GRADE_WINDOW_DAYS`); từ chối nếu entry mới nhất không phải CREATE/UPDATE (`not-clean` — chống undo lặp/mất sửa tay); semester lock + access check trong cùng tx (ADR-016 S24). - **Student Roster Import Boundary (ADR-064, 2026-08-28)** — Excel/CSV/TXT được parse client-side có cap 10 MB/2000 dòng rồi gửi JSON tới `/api/students/validate|import`. Server là authority cho normalize, validation, parish-wide duplicate guard và quyết định fail-closed (`skip` mặc định; `update/create` phải explicit). Chủ nhiệm không nhận metadata collision ngoài lớp được phân công. Partial-success ADR-008 giữ nguyên. Undo roster 24h dùng `import_batch_students.rollback_snapshot` exact theo row/batch; audit vẫn redacted và không còn là restore source; snapshot TTL, post-import mutation/dependency gate và exact created-class IDs bảo vệ dữ liệu.
- **Roster Import Fast Commit + Immediate Projection (ADR-066, 2026-08-28)** — create-only rows đã validate, không collision và resolve được lớp đi qua fast path chunk 40: multi-row `students` + `audit_logs` + `import_batch_students` (+ `service_assignments` khi có) trong cùng transaction; lỗi constraint/race rollback nguyên chunk rồi fallback transaction từng dòng, nên partial-success/rollback ADR-008/064 không đổi. Năm học cache theo lớp, mã `TN{year}{6}` được reserve từ một snapshot code scoped giáo xứ và UNIQUE DB vẫn là final guard. Response trả `studentChanges` chỉ gồm record đã commit; `studentStore.reconcileImportedStudents` kiểm tra tenant scope và merge ngay, không GET lại tối đa 10.000 học viên khi đóng modal. Lớp mới refresh nền; undo vẫn refetch authoritative.

## 2. Layer Boundaries & Dependency Rules

| Layer | Can Import From | Cannot Import From |
| :--- | :--- | :--- |
| `pages/` | `components/`, `stores/`, `hooks/`, `utils/`, `lib/` | `server/` |
| `components/` | `stores/`, `hooks/`, `utils/`, `lib/` | `pages/`, `server/` |
| `stores/` | `lib/`, `utils/`, `types/` | `components/`, `pages/`, `hooks/` |
| `hooks/` | `stores/`, `lib/`, `utils/` | `components/`, `pages/` |
| `lib/` | `types/` | `stores/`, `components/`, `pages/`, `hooks/` |

## 3. Security Envelope

- **Auth** — JWT HS256 (access 15m, refresh 7d, tách `JWT_SECRET`/`JWT_REFRESH_SECRET` bắt buộc ở production), bcrypt 12 rounds (A-NEW-19, 2026-08-11: upgrade từ 10 theo OWASP, rehash-on-login cho hash legacy cost 10), `tokenVersion` validated on every request (revoked on logout & password reset), `failedAttempts` auto-lock at 5 (atomic SQL increment — A-NEW-19 fix TOCTOU lost update). **Refresh token rotation** (`refresh_tokens` — lưu sha256 hash, rotate mỗi `/refresh`, reuse detection thu hồi toàn bộ phiên khi phát hiện đánh cắp; logout per-session). **A01 Phase 1 (2026-08-10)**: refresh token chuyển sang **HttpOnly cookie** `parish_refresh` (`Secure` ở production, `SameSite=Lax`, `Path=/`, 7 ngày; client `credentials:'include'`; `/refresh` đọc cookie trước, body chỉ là backward-compat). Access token (15m) giờ **memory-only** (A-NEW-10/20, 2026-08-11: không persist localStorage — XSS không lấy được; sau reload bootstrap lại qua `/auth/refresh` cookie HttpOnly). **A01 Phase 2 (2026-08-10)**: XSS sinks đã đóng — `ReportExportService` không còn `document.write` (Blob URL/srcdoc); print popup escape toàn bộ field user; A01 đã đóng P1. **ADR-045 (2026-08-16)**: session state persist 2 tầng — localStorage `parish_current_user` chỉ chứa **marker không-PII** `{id, role, parishId}` (guard đồng bộ); snapshot đầy đủ (username/fullName/phone) **mã hóa AES-256-GCM tại-rest trong IndexedDB** (`parish_auth_user`, dexieStorage, khóa non-extractable, AAD + tenant-scope); snapshot hỏng/thiếu → rebuild qua `GET /auth/me` khi online (offline → logout sạch); mọi đường session chết dọn cả marker lẫn snapshot (A-NEW-54).
- **Authorization (RBAC)** — 4 roles (`admin`, `chunhiem`, `phuta`, `phuhuynh`); `roleMiddleware` on all routes + `checkUserClassAccess` for class-scoped roles.
- **Multi-Tenant Isolation (Plan v2)** — **Mọi query phải mang `parish_id`**; read-back không ngoại lệ. Cross-parish read/write bị chặn trước khi check quyền chi tiết (sai parish → 404, không lộ sự tồn tại). Mọi định danh đều composite hóa theo ADR-031 — kể cả `users.username` → `UNIQUE(parish_id, username)` (`idx_users_username_parish`, ADR-046, migration `20260816-121`); login lookup theo parish (body `parishId` optional default `'gia-ton'`). Test suite: `server/src/__tests__/security/tenantIsolation.test.ts` (15 tests — cross-parish read/write + class-scope isolation; ✅ pass 2026-08-09, full suite 919/919 + `tsc -b` sạch) + `server/src/__tests__/username-tenant-scope.test.ts` (5 tests — ADR-046).
- **Input validation** — Zod schemas on all endpoints (trim, enums, max lengths); 10MB body limit; batch arrays cap tường minh (SEC-BATCH-CAP-1, 2026-08-24: import rows ≤2000, grades batch ≤2000, attendance records ≤500).
- **QR report-card signing** — HMAC-SHA256 qua `REPORT_HMAC_SECRET` **bắt buộc production** (SEC-HMAC-1, 2026-08-24: fail-closed module-level như JWT_SECRET; verify giữ legacy chain để QR cũ còn xác thực; không còn literal public trong source).
- **Security headers** — CSP, HSTS, X-Frame-Options `DENY`, `nosniff`, Referrer-Policy, Permissions-Policy; CSP violation reports thu tại `POST /api/csp-report` (public, rate-limited — OBS-1, 2026-08-24).
- **Rate limiting** — in-memory Map: 1000 req/60s per IP general, 10 req/60s login (resets on restart; acceptable for single-parish scale).
- **Data safety** — destructive ops (purge/restore) snapshot qua `safetySnapshot.ts` + `blobStorage.ts` (ADR-041). SQLite local dùng `VACUUM INTO`; Turso remote dùng read-transaction logical snapshot, checksum SHA-256, gzip + AES-256-GCM và R2 độc lập (`BACKUP_ENCRYPTION_KEY`, ADR-059). Restore remote chỉ qua CLI drill, target cô lập đã migrate, explicit flag và guard chống URL production. Disk Render là ephemeral nên remote production không được fallback local.

## 3.1 Production delivery authority (ADR-057)

Push `main` không tự deploy. GitHub CI phải hoàn tất secret scan → lint zero-warning/design guard → typecheck → coverage tests → build → Playwright. Chỉ workflow `Production Deployment Gate` sau `workflow_run=success` mới được gọi Vercel và Render bằng đúng immutable SHA, đợi cả hai live và smoke-check. Nếu SHA không còn là HEAD hoặc thiếu production secret, deployment dừng fail-closed.
