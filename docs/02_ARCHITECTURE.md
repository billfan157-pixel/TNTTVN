### Key Architectural Characteristics

- **Modular Monolith / Workspace Platform (ADR-082)** — Một deploy, một auth/backend/database/design system; presentation được chia thành `academic`, `organization`, `parent`. Workspace là information architecture, không phải security boundary. `/dashboard` giữ học vụ, `/parish` là dashboard Xứ đoàn, `/parent` giữ Parent Portal. `RootLayout` nhớ workspace gần nhất theo parish+account; desktop sidebar và mobile control sheet chuyển workspace không logout. Backend `roleMiddleware`/tenant checks vẫn là authority.
- **Single-Parish Deployment / Tenant-Scoped Persistence (ADR-106)** — Mỗi production deployment được khóa vào đúng một `DEPLOYMENT_PARISH_ID`; login, public recovery, token issue/verify, seed, backup và background workers không cho client/caller chọn giáo xứ khác. Startup quét động mọi bảng có `parish_id` và từ chối bind HTTP nếu gặp row null/khác scope. Schema vẫn giữ `parish_id`, composite key/FK/query predicate và cache namespace `parishId:userId` như defense-in-depth, restore/import boundary và khả năng test cross-tenant; đây không phải shared multi-parish production runtime.
- **Parish Memory bounded context (ADR-081)** — `/api/parish-profile` sở hữu profile, identity tổ chức, cây đơn vị, nhiệm kỳ, record lịch sử, asset và quan hệ. `parish_events` vẫn là lịch tác nghiệp; timeline là read model suy ra, không có writer/table riêng. `parish_people.linked_user_id` liên kết account tùy chọn và partial unique index bảo đảm một account không sinh nhiều identity active.
- **Parish Event client boundary (ADR-098)** — `parish_events` tiếp tục do REST/server DB sở hữu. Client chỉ project create/update/delete sau server acknowledgement; cache đọc nằm trong encrypted `dexieStorage` theo `parishId:userId`, không dùng global plaintext localStorage, không tạo mutation cục bộ hoặc delete lạc quan. Store kiểm exact tenant trên response và bỏ kết quả request nếu scope đã đổi. Lịch phụng vụ thuật toán vẫn offline độc lập; durable offline event write là future reassessment cần idempotency receipt.
- **Operational integrity & output boundary (ADR-099)** — attendance, parish-event và native-token mutations commit domain row + redacted audit trong cùng database transaction; ngày nghiệp vụ dùng validator lịch thật thay vì chỉ regex. Undo-import marker và native enable/disable preference đều scope `parishId:userId`; personnel paste import là một admin-only all-or-nothing server command tối đa 100 rows. Mọi HTML print/preview escape dữ liệu user, đi qua Blob URL thay vì `document.write`, tách `window.opener` và sandbox `srcDoc` iframe. Đây là lớp hardening, không thay RBAC/tenant authority hoặc tạo schema mới.
- **Login Gate & Security Envelopes** — **2 cổng đăng nhập UI, chung 1 backend auth (ADR-044/058/087)**: `/login` (chọn cổng) → `/login/phuhuynh` (SĐT + mật khẩu; quên mật khẩu tạo ticket cho Admin, sau đó BGL xác minh qua kênh tin cậy) hoặc `/login/nhan-su` (tên đăng nhập + mật khẩu, liên hệ BGL khi quên). **1 tài khoản = 1 vai trò** (`users.role` enum): đăng nhập sai cổng → role gate logout + chỉ đường sang cổng đúng (GLV kiêm PH dùng 2 tài khoản riêng). Backend dùng `POST /api/auth/login`; credential chỉ lưu bcrypt hash, mật khẩu tạm trả đúng một lần, không có reveal/KBA self-reset. Public ticket trả response generic + bcrypt timing work, rate-limit 5/60s/IP, dedupe một row `(parish_id,user_id)`; chỉ admin cùng tenant thấy inbox và reset atomic sau re-auth.
- **RBAC & Class Scope Guards (ADR-072/089/090/092)** — `roleMiddleware` and `checkUserClassAccess` remain server authority across REST endpoints. Client route/navigation/title state derives from `src/constants/routePolicy.ts`: parent-only `/parent`; staff workspaces `/students|grades|attendance|reports|leave-requests`; `/catechists` là danh bạ staff read-only nhưng ghép thêm management actions chỉ cho admin. `GET /api/students` và `GET /api/students/:id` bắt buộc role `admin|chunhiem|phuta`; phụ huynh bị 403 và chỉ đọc con qua `/api/parents/my-children`. Trong cùng tenant, GLV đọc roster/metadata lớp toàn giáo xứ nhưng không nhận assignment identity; ghi student theo lớp, điểm danh/điểm/thi và controls quản trị vẫn bị chặn theo quyền. `GET /api/classes` chỉ thêm boolean `assignedToCurrentUser` cho GLV; `ExamSessionView` dùng marker này để lọc fail-closed controls/lớp thi về đúng assignment, còn server tiếp tục kiểm `getUserClassIds` cho mọi read/write phiên chấm. Tab quản lý lớp chỉ admin; hidden navigation is not authorization authority.
- **Automatic Viewport Adaptation (`useEffectiveMode`)** — Mobile/tablet shell applies below 1024px; desktop shell begins at ≥1024px. Explicit desktop mode is ignored below the floor and forced-mobile is normalized to desktop above it so JS mode and CSS guard cannot diverge.
- **Presentation System v4.5 (`App-wide Calm, Confident Parish Product`, ADR-063/065/072/077/078/079/080)** — `src/index.css` là entrypoint duy nhất của ordered graph `src/styles/design-system/00-* → 70-*`; token/cascade ownership được khóa bằng graph contract và production-output comparison. Typed primitives tại `components/common/ui` chuẩn hóa button/form/tab/panel/radio/filter/badge/surface semantics mà không tạo framework hoặc business mapping mới. `PageHeader`, product-view/panel/toolbar/entity/state/auth primitives và desktop/mobile shells tạo một visual grammar dùng chung; ở phone, khối identity/action của `PageHeader` có flex-basis rõ ràng để action không ép hoặc cắt tiêu đề. `DesktopAppShell` dùng `.responsive-page-shell` ở touch/tablet và tier rõ ràng từ desktop 1024px; `embedded-page-section` không sở hữu gutter/max-width lần hai. `PageTransition` + TanStack Router View Transition tạo fade-through ngắn cho pathname change trong vùng content, giữ shell đứng yên; `prefers-reduced-motion` tắt route motion. `lazyWithRetry` cung cấp TanStack-compatible `.preload()`; `useMobileRoutePreload` làm ấm tuần tự primary chunk theo role trong idle time và bottom nav preload theo pointer/focus, nên chunk readiness xảy ra trước fade-through thay vì tạo khoảng đứng trước animation. Browser lifecycle abort/invalid-state/timeout được consume ở `ready`/`finished`, còn `updateCallbackDone` tiếp tục nổi lỗi ứng dụng. `useAccessibleDialog` + `ModalPortal` chuẩn hóa lifecycle/root layering.
  - **Governance:** `lint:ds` v4.5 chạy 8 source rules trên 119 application TSX và hiện có 0 violation. Per-file ratchet giữ ceiling theo file; kết quả static này không tự chứng nhận WCAG hoặc visual conformance.
  - **Runtime evidence:** 5 route bảo vệ đại diện (`/dashboard`, `/students`, `/attendance`, `/grades`, `/finances`), 4 public/auth routes và `ParentForgotPasswordModal` được kiểm ở 1440/390/320 × light/dark: tổng 60 Axe observations và 60 full-page visual/layout captures; thêm một test điều hướng mobile-bottom-nav thật. Protected traversal dùng sidebar trong cùng SPA document, assert canonical URL + `aria-current` + `.product-view`, rồi đợi hết primary loading status trước scan/capture. PNG là evidence artifact, không phải pixel-diff baseline.
  - **Risk-based isolated E2E harness (ADR-093):** Playwright dùng riêng Vite/API 3100/3101, SQLite UUID + owner marker trong OS temp, deterministic synthetic seed, không nạp server `.env`, scrub remote/external DB env, preflight port, chỉ phát `READY` sau Vite/API/seed và cleanup qua reporter. Zoom lock vẫn là explicit WCAG exception; browser E2E không chứng nhận screen reader, physical camera/biometric, OMR field corpus hoặc thiết bị thật.
- **Capacitor Native Shell (ADR-029/088/092)** — Dual-platform: Web PWA và native Android/iOS qua Capacitor 8, appId `com.tnttvn.app`, product label `Catevia`, webDir `dist`. Native production API là `https://tnttvn.onrender.com/api`; dev web proxy `/api` và `/health` tới Hono local. Service worker chỉ đăng ký trên web; native unregister worker/cache PWA cũ. Android fail-closed với `allowBackup=false` cộng backup/data-extraction rules loại toàn bộ app data, chỉ xin `CAMERA` (camera optional vì còn đường tải ảnh) và FileProvider chỉ expose app-specific external files/cache. iOS chỉ khai báo camera, không khai báo microphone vì mọi `getUserMedia` dùng `audio:false`. CI Android hiện tạo debug APK; signed Android release và kiểm thử camera/biometric trên thiết bị thật vẫn là external gate.
- **Web Delivery Security, Release Provenance & Cold Start (ADR-092/100)** — Vercel áp CSP cho HTML tĩnh với `script-src 'self'`, `style-src-attr 'unsafe-inline'` tách khỏi element style, `frame-ancestors 'none'`, `object-src 'none'`, nosniff, referrer và Permissions-Policy `camera=(self), microphone=()`. Theme pre-paint là file `/theme-boot.js`, không còn inline script. Vercel Git auto-deploy bị khóa trong config; build inject meta `catevia-release` đã sanitize, backend `/health` trả public non-secret `releaseId`, và post-deploy gate bắt buộc cả hai bằng exact CI `VERIFIED_SHA`. `/health` được proxy riêng tới Render để System Diagnostics nhận JSON thật; refresh-cookie bootstrap có AbortSignal 65 giây để bao phủ một cửa sổ cold start nhưng không treo vô hạn. Nâng Render always-on vẫn là quyết định vận hành/chi phí ngoài repo.
- **Native Biometric App Lock (ADR-085, 2026-08-31)** — `BiometricLockGate` nằm ngoài `RouterProvider`: cold start có preference hợp lệ sẽ không mount protected route cho tới khi native OS xác minh thành công. `@aparajita/capacitor-biometric-auth` 10 dùng LocalAuthentication/BiometricPrompt cho Face ID, Touch ID, Android face/fingerprint; `@capacitor/app` khóa lại khi app chuyển inactive, kiểm tra lại strong-biometry availability rồi tự gọi prompt khi active. Preference chỉ là marker `enabled` scope theo `parishId:userId`; không chứa PII, credential, ảnh hoặc biometric template. Tắt khóa cũng cần biometric; nếu sensor mất enrollment/lockout, recovery duy nhất trong lock screen là xóa marker + logout client state rồi đăng nhập lại bằng mật khẩu. App lock là local privacy barrier, **không phải** server MFA/passkey và không thay JWT/refresh/RBAC/tenant authority. Web/PWA không giả lập biometric lock.
- **Offline Sync Engine (`syncCoordinator` + `useSyncEngine`)** — `syncCoordinator.ts` sở hữu imperative 4-phase push + delta pull; `syncTrigger.ts` là seam không import store/hook để store chỉ phát yêu cầu; React hook chỉ đăng ký runner và sở hữu online/offline/timer lifecycle. Architecture gate cấm store import hook (ADR-105):
  - Store mutation phải hoàn tất ghi operation vào Dexie trước khi gọi `runSyncFlow`; grade/attendance dùng promise chaining để sync engine không đọc queue quá sớm.
  1. **Phase 1 — Compact & Flush**: merge duplicate ops in the queue, then flush batched UPDATEs. Safe compaction rule: `CREATE` + `DELETE` pairs only canceled if `CREATE` is unsent local-only (`pending` status, `retryCount` 0). If `CREATE` has retried, keep BOTH `CREATE` and `DELETE` so Phase 1.5 retries `CREATE` with `idempotencyKey`, remaps Temp ID to Server Real ID, and Phase 3 executes `DELETE` with real ID (zero lost mutation).
  2. **Phase 1.5 — Parent CREATEs first**: parent entities (student/class/notice/exam) are created with `idempotencyKey` and client temp IDs remapped to server IDs BEFORE dependents sync.
  3. **Phase 2 — Group batchable ops**: grade/attendance UPDATEs grouped into batch requests.
  4. **Phase 3 — Individual ops**: student/class/notice/exam CREATE, DELETE and non-UPDATE ops processed one-by-one.
  Then **Pull Delta** (`fetchAllData`) refreshes client state.
  - Conflict handling: LWW field-level merge on version conflict for Grade/Attendance (client edit kept), Server-Wins for Student/Class/Notice/Exam CRUD (with explicit Toast separation). Strict Optimistic Concurrency Control (OCC) version enforcement, exponential backoff. Retry thresholds: server/client errors retry up to 3 (`MAX_RETRIES`), network errors bypass the cap up to 5 attempts. Dexie operations wrapped in atomic `db.transaction`. User isolation enforced fail-closed (`isOwnOp`) with 1-time `migrateLegacyQueueUserIds`.
- **CQRS Read Model Projections** — `ReportingApplicationService` owns authorization, parish policy/date-range resolution and one transaction snapshot. Pure SQL read repositories (`ReportCardProjectionRepository`, `ClassSummaryProjectionRepository`) receive that executor + immutable context and remain separate from write models (4 Drizzle write repositories); architecture tests reject repository → service imports (ADR-104).
- **Fail-Closed Database & Deployment Readiness (ADR-051/106)** — `db/index.ts` vẫn thực thi bootstrap + versioned migrations, nhưng `server/src/index.ts` bắt buộc gọi schema readiness và single-parish data preflight **trước seed, bind HTTP port và background workers**, rồi kiểm lại parish scope sau seed. Gate schema kiểm migration manifest, tenant/data-integrity indexes/triggers, composite PK và `foreign_key_check`; gate deployment khám phá mọi table có `parish_id` và chỉ cho exact configured parish. Bất kỳ partial schema hoặc mixed/null parish data đều làm startup fail-closed; không có auto-rewrite/purge để làm gate xanh.
- **Atomic Finance Command Boundary (ADR-051, 2026-08-21)** — mọi Finance write (`createFund`, `createTransaction`, `deleteTransaction`, `updateStudentFee`) có implementation duy nhất trong `FinanceApplicationService` và chạy qua `runDbTransaction`. `updateStudentFee` tái sử dụng `createTransactionInTx` để payment ledger + audit + fee record dùng cùng transaction, không nested transaction; legacy `financeService.ts` chỉ giữ query/read logic và re-export command để import cũ không bypass ACID boundary.
- **Risk-baseline invariant hardening (ADR-101, 2026-09-03)** — Dexie queue/conflict ownership là exact `(parishId,userId)` và bất biến; row legacy thiếu một trong hai bị quarantine thay vì gán cho phiên đăng nhập mới. Grade override/restore đọc policy version, semester lock, student class và assignment qua cùng write transaction. Finance fee update reconcile một linked receipt thay vì append; batch thu cả lớp là một transaction. Multi-statement migrations bọc `BEGIN IMMEDIATE` và ghi marker trong cùng commit. Notice delete là tombstone; `parent_revoked_at` chỉ cho phép delta gửi redacted eviction khi một notice từng-visible đổi sang staff, không tiết lộ notice nội bộ mới.
- **Durable Notification Worker (ADR-102, 2026-09-03)** — `notifications` là queue authority, không còn chỉ là history: enqueue chỉ resolve sau durable INSERT; `delivery_kind`, `attempt_count/max_attempts`, `next_attempt_at` và DB claim lease giữ nguyên dispatch intent và ngăn hai replica cùng dispatch một row. Startup drain, retry wake-up và poll thu hồi lease hết hạn. Audience `target_user_ids` vẫn tenant-scoped SSOT cho Telegram/Web/native; target JSON hỏng fail-closed thành tập rỗng, provider chưa cấu hình, partial push failure hoặc Telegram delivery throw không được đánh dấu `sent`. Delivery là at-least-once: crash sau provider accept nhưng trước DB acknowledgement vẫn có thể gửi lặp và cần provider-level idempotency/per-recipient receipts nếu yêu cầu nâng cao.
- **Academic Finalization, Policy Read & Local Backup Hardening (ADR-103, 2026-09-04)** — `finalizeYear` đặt terminal/semester-lock guard, completeness checklist, source/policy reads, promotion specification, snapshot upsert, year lock và audit trong cùng `runDbTransaction`; mọi helper nhận cùng executor. Parish policy và academic-year range chỉ fallback khi row/config business vắng hoặc không hợp lệ; lỗi query/infrastructure propagate và rollback decision/write path. Local SQLite backup chỉ publish file sau `VACUUM INTO` vào unique partial artifact rồi atomic rename; checkpoint có thể degraded nhưng `VACUUM INTO` lỗi sẽ fail run, xóa partial, không upload/retention/ghi daily marker và không raw-copy main DB thiếu WAL.
- **Remaining Audit Boundary Hardening (ADR-104, 2026-09-04)** — base grade upsert/undo resolve policy version trong write transaction; reporting application service truyền một transaction/policy context xuống projection repositories; retryable batch-promotion callbacks không mutate response state; và `server/src/index.ts` là composition root duy nhất sở hữu signal/shutdown cho HTTP, schedulers, notification delivery, Puppeteer, Telegram và DB.
- **Recovery, Tenant Scheduler & Dependency Seams (ADR-105, amended by ADR-106)** — promotion transition persist target year và có durable reconciliation derived từ snapshot/promotion rows; retry chỉ xử lý item unresolved, archive fail closed. Sunday scheduler giữ marker/recipient tenant-scoped và isolation semantics, nhưng production enumeration nay bị khóa vào deployment parish; multi-parish composition chỉ còn ở dev/test. Remote restore yêu cầu target fingerprint, empty/schema-compatible target, row-count/FK/schema verification. Domain policy ports không còn DB/JWT type; adapters bind đúng transaction executor, application services không phụ thuộc HTTP middleware. Client sync cycle và dead GradeAggregate path đã được loại bỏ.
- **Reporting current scope (ADR-010 amendment, 2026-09-05)** — current MVP có đúng hai server CQRS projections: report card và class summary. `ParishSummaryProjection` là deferred candidate, không phải runtime defect; chỉ mở lại sau product contract rõ ràng.
- **Architecture inventory gate** — `npm run lint:architecture-inventory` đếm current Hono route modules, services, repositories, domain modules và Drizzle tables; CI fail nếu các số public trong sơ đồ này drift khỏi source.
- **Scan Engine v4 trust + performance boundary (ADR-049/050/060/062)** — Camera/QR/OMR xử lý on-device; T3 ràng buộc identity + template + số câu + mã đề A–H vào checksum, còn T2/TE/legacy map về A. Live QR xen 3 lượt `live_fast` (3 ROI thường) với 1 lượt `live_recovery` (một crop focus phóng 2×), đều không inversion; explicit capture/file/batch mới dùng `exhaustive` 9 normal + 4 `invertFirst`; Code128 giữ fallback ở mọi mode. Detector chuẩn bị grayscale+SAT một lượt, tái sử dụng SAT giữa locators, short-circuit marker thiếu và dùng scratch arena ≤2,5 triệu pixel; ảnh still lớn hơn dùng buffer cục bộ, arena được zeroize/release khi camera hoặc batch kết thúc. Auto camera dùng 960px cho candidate đầu, 1280px cho QR/recheck/frame xác nhận cuối; fixed-student still tối đa 2200px và upload tối đa 1400px. RAF gọi callback cấu hình mới nhất và backpressure neo sau thời điểm xử lý xong; async generation token chặn capture/upload/batch tiếp tục sau unmount; 2-frame consensus, mọi marker/paper/geometry/confidence gate và server recompute giữ nguyên. Quality bad chặn sớm; live batch giữ stream, file batch commit UI mỗi 8 ảnh nhưng yield sau từng ảnh và accepted-only proposal. `scan_metadata` cấm ảnh và gắn `omr-v4-*`; diagnostics local v2 chỉ histogram/counter, snapshot rà soát vẫn opt-in AES-GCM local TTL 24h, không upload. KPI MC tách exact engine/device/runtime/resolution/template/questionCount/cold-warm và required matrix rỗng/missing fail-closed; corpus camera ADR-060 chưa đủ nên unattended/default auto-batch vẫn CONDITIONAL, score-grid written luôn manual-confirm; SBD/OCR tiếp tục đóng.
- **Supervised Continuous OMR Queue (ADR-067/107)** — Khi người chấm bật `Quét liên tiếp`, explicit Save ghi trước một mutation mã hóa riêng theo `sessionId + studentId`, optimistic result và durable item ledger; camera re-arm ngay mà không chờ network/full refresh. Queue claim nguyên tử `pending|retrying → processing` trước network I/O; compaction chỉ đụng op chưa claim, processing lease hết hạn được phục hồi. Vì vậy payload mới không thể thay request đang in-flight; ledger chỉ `superseded` khi hai mutation thật sự dùng chung queue ID. `complete` là session barrier sau các save/remove chưa terminal. Attempt fingerprint chặn duplicate, same-student/different-attempt phải xác nhận conflict. Server receipt theo `(parish,user,clientMutationId)` xử lý response-loss retry, còn `resultVersion/expectedResultVersion` + SQL compare-and-swap chặn stale device/tab; conflict không tự replay. `VITE_CONTINUOUS_SCAN_V2` là rollback flag; human-confirm/privacy/field gates giữ nguyên.
- **Continuous OMR Phase 2–3 readiness (ADR-068/069, 2026-08-28)** — Paper-ROI quality chạy shadow sau marker/paper gate, trong khi global quality vẫn quyết định acceptance. ## 3. Security Envelope

- **Auth** — JWT HS256 (access 15m, refresh 7d, tách `JWT_SECRET`/`JWT_REFRESH_SECRET` bắt buộc ở production), bcrypt 12 rounds (A-NEW-19, 2026-08-11: upgrade từ 10 theo OWASP, rehash-on-login cho hash legacy cost 10), `tokenVersion` validated on every request (revoked on logout & password reset), `failedAttempts` auto-lock at 5 (atomic SQL increment — A-NEW-19 fix TOCTOU lost update). **Refresh token rotation** (`refresh_tokens` — lưu sha256 hash, rotate mỗi `/refresh`, reuse detection thu hồi toàn bộ phiên khi phát hiện đánh cắp; logout per-session). **A01 Phase 1 (2026-08-10)**: refresh token chuyển sang **HttpOnly cookie** `parish_refresh` (`Secure` ở production, `SameSite=Lax`, `Path=/`, 7 ngày; client `credentials:'include'`; `/refresh` đọc cookie trước, body chỉ là backward-compat). Access token (15m) giờ **memory-only** (A-NEW-10/20, 2026-08-11: không persist localStorage — XSS không lấy được; sau reload bootstrap lại qua `/auth/refresh` cookie HttpOnly). **A01 Phase 2 (2026-08-10)**: XSS sinks đã đóng — `ReportExportService` không còn `document.write` (Blob URL/srcdoc); print popup escape toàn bộ field user; A01 đã đóng P1. **ADR-045 (2026-08-16)**: session state persist 2 tầng — localStorage `parish_current_user` chỉ chứa **marker không-PII** `{id, role, parishId}` (guard đồng bộ); snapshot đầy đủ (username/fullName/phone) **mã hóa AES-256-GCM tại-rest trong IndexedDB** (`parish_auth_user`, dexieStorage, khóa non-extractable, AAD + tenant-scope); snapshot hỏng/thiếu → rebuild qua `GET /auth/me` khi online (offline → logout sạch); mọi đường session chết dọn cả marker lẫn snapshot (A-NEW-54).
- **Authorization (RBAC)** — 4 roles (`admin`, `chunhiem`, `phuta`, `phuhuynh`); `roleMiddleware` on all routes + `checkUserClassAccess` for class-scoped roles.
- **Tenant Safety Namespace (ADR-031/046/106)** — **Mọi query vẫn phải mang `parish_id`**; read-back không ngoại lệ. Cross-parish read/write bị chặn trước khi check quyền chi tiết (sai parish → 404, không lộ sự tồn tại). Mọi định danh tiếp tục composite hóa, kể cả `users.username` → `UNIQUE(parish_id, username)`. Production login lookup luôn dùng `DEPLOYMENT_PARISH_ID`; legacy body không chọn tenant. Multi-parish regression còn chạy ở dev/test để chứng minh isolation, dù topology production là một parish mỗi deployment.
- **Input validation** — Zod schemas on all endpoints (trim, enums, max lengths); 10MB body limit; batch arrays cap tường minh (SEC-BATCH-CAP-1, 2026-08-24: import rows ≤2000, grades batch ≤2000, attendance records ≤500).
- **QR report-card signing** — HMAC-SHA256 qua `REPORT_HMAC_SECRET` **bắt buộc production** (SEC-HMAC-1, 2026-08-24: fail-closed module-level như JWT_SECRET; verify giữ legacy chain để QR cũ còn xác thực; không còn literal public trong source).
- **Security headers** — CSP, HSTS, X-Frame-Options `DENY`, `nosniff`, Referrer-Policy, Permissions-Policy; CSP violation reports thu tại `POST /api/csp-report` (public, rate-limited — OBS-1, 2026-08-24).
- **Rate limiting** — in-memory Map: 1000 req/60s per IP general, 10 req/60s login (resets on restart; acceptable for single-parish scale).
- **Data safety** — destructive ops (purge/restore) snapshot qua `safetySnapshot.ts` + `blobStorage.ts` (ADR-041). SQLite local dùng `VACUUM INTO` vào partial artifact rồi atomic rename; lệnh lỗi làm backup fail closed, không copy riêng main DB khi WAL có thể còn committed pages (ADR-103). Turso remote dùng read-transaction logical snapshot, checksum SHA-256, gzip + AES-256-GCM và R2 độc lập (`BACKUP_ENCRYPTION_KEY`, ADR-059). Restore remote chỉ vào target cô lập đã migrate: command cần SHA-256 fingerprint xác nhận target, preflight target rỗng + schema/cột tương thích, rồi read-back row counts, `foreign_key_check` và schema readiness; không restore thẳng production (ADR-105). Disk Render là ephemeral nên remote production không được fallback local.

## 3.1 Production delivery authority (ADR-057)

Push `main` không tự deploy. GitHub CI phải hoàn tất secret scan → lint zero-warning/design guard → typecheck → coverage tests → build → Playwright. Chỉ workflow `Production Deployment Gate` sau `workflow_run=success` mới được gọi Vercel và Render bằng đúng immutable SHA, đợi cả hai live và smoke-check. Smoke bắt buộc đối chiếu frontend meta + backend health `releaseId` với `VERIFIED_SHA`, xác nhận unauthenticated `/api/auth/me` trả 401 và kiểm CSP/HSTS. Nếu SHA không còn là HEAD, release lệch, security header thiếu hoặc thiếu production secret, deployment dừng fail-closed.

## 5. Durable Delta Sync and Exam Variant Boundary (ADR-094)

- `GET /api/sync/watermark` establishes a server-clock snapshot boundary. A tenant/user-scoped cursor in Dexie is advanced only after all participating store pulls succeed.
- Students and classes page by stable `(updated_at,id)` order inside a bounded window and return soft-delete tombstones during incremental pulls. Full pull remains the bootstrap and empty-cache repair path.
- `navigator.locks` coordinates tabs when supported; the expiring localStorage lease is the compatibility fallback. Neither replaces server idempotency, tenant scope, version checks, or transaction boundaries.
- `exam_sessions.variant_manifests` is the immutable source for generated A–H question/option permutations. The server generator materializes each version and locks answer-key mutation; clients only render/print a non-A question document when that exact manifest exists.
- Exam import, scan, paper, batch, analytics, variants, and guided-grade surfaces are separate lazy chunks beneath `ExamSessionView`. SheetJS remains on-demand through `xlsxLoader`; the PWA manifest excludes `xlsx-*.js` from install-time precache and the existing static-resource route caches it after first use.
- Virtualization and OMR Worker/adaptive-threshold work are not architecture defaults. They require view/device traces and the ADR-060/068/069 corpus gates before selection.

## 6. Question Bank to Smart Exam Boundary (ADR-096)

`QuestionBankView → /api/question-bank → questionBankService` is the authoring and blueprint path. The service owns lifecycle, immutable versions, tenant scope, deterministic selection and one transaction that checks class assignment, reads active/current bank versions and materializes a normal `exam_sessions` record. Build commands carry a client-stable `buildCommandId`; the service derives a stable seed when absent and persists a canonical request hash with the session, so response-loss retry returns the same materialization while key reuse with different input conflicts. Every create/revise/import/blueprint path validates optional `branch_id` against the same tenant inside its write transaction. `examQuestionSnapshots` binds every session position to the exact bank version and content hash; grading, variants, OMR and finalization continue through existing Exam services.

The dependency direction is one-way: Question Bank may create an Exam, but an Exam never reads mutable current bank content while rendering or scoring. Blueprint shortage and unsupported materialization types fail before session insert. Authoring/build are online-only; no new client sync entity or second scoring authority is introduced.

Branch/class selection reuses the existing class catalog without coupling reusable content to a year-specific roster row: UI class IDs are transient and map to persisted `branch_id + curriculum_level=class.name`. Direct `.xlsx|.xls|.csv|.docx` imports are parsed and previewed client-side; only normalized question JSON crosses the API boundary. `POST /questions/import` validates the whole batch and tenant branch references, then writes draft items, immutable versions and audit metadata in one database transaction.

SheetJS and pinned Mammoth are lazy document chunks excluded from PWA install-time precache. Import is capped at 5 MB/50 parsed questions per file; server batch capacity is 100 normalized items. This is an authoring convenience only: it cannot activate questions, bypass lifecycle/RBAC, introduce a second file-storage path or change Smart Exam/OMR authority.
